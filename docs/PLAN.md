## 1. Problem, Metric & Environment

### 1.1 Problem Formulation
The goal is to classify approximately 4,000 unlabeled text passages (lengths ranging from 40 to 250 words) into one of 18 LLM classes across 6 leading AI research labs. The passages represent responses generated by frontier and lightweight models:

- **OpenAI (5 classes):** `gpt-5.5`, `gpt-5.6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-6-astra`
- **Google (4 classes):** `gemini-3.1-pro-preview`, `gemini-3.6-flash`, `gemini-3.7-flash`, `gemini-3.8-flash`
- **Anthropic (5 classes):** `claude-fable-5`, `claude-opus-4-6`, `claude-opus-4-8`, `claude-opus-5`, `claude-sonnet-5`
- **Qwen (1 class):** `qwen3.8-max`
- **ZAI (2 classes):** `glm-5.3`, `glm-5.3-flash`
- **Moonshot (1 class):** `kimi-k3`

Passages are short (40–250 words), meaning topical semantics may be shared across multiple models responding to the same prompt, while subtle stylometric signals (punctuation habits, list formatting, whitespace nuances, sentence rhythm, lexical diversity, token probabilities) differentiate the generating models.

### 1.2 Evaluation Metric
The official competition evaluation metric is **Balanced Accuracy**, defined as the unweighted macro-average of recall across all $K = 18$ classes:

$$\text{Balanced Accuracy} = \frac{1}{K} \sum_{k=1}^{K} \text{Recall}_k = \frac{1}{K} \sum_{k=1}^{K} \frac{\text{TP}_k}{N_k}$$

Where:
- $K = 18$
- $\text{TP}_k$ is the number of true positive classifications for class $k$.
- $N_k$ is the total number of ground truth instances belonging to class $k$.

Balanced accuracy penalizes systems that neglect rare classes to optimize raw accuracy. Under unequal and potentially shifting test class priors (between public and private leaderboards), standard posterior maximization ($\text{argmax}_k P(y=k \mid x)$) is suboptimal. The baseline decision rule must normalize by the training class priors:

$$\hat{y} = \arg\max_{k \in \{1,\dots,18\}} \frac{P_{\text{train}}(y=k \mid x)}{\pi_{\text{train}}(k)}$$

Where $\pi_{\text{train}}(k) = \frac{N_k}{N_{\text{train}}}$ is the observed training prior of class $k$.

### 1.3 Submission & Runtime Environment
- **Environment:** Kaggle Notebook runner with **internet disabled**.
- **Time Limit:** Strictly $\le 9.0$ hours total execution time.
- **Input:** Reads `test.csv` (contains passage `id` and text).
- **Output:** Writes `submission.parquet` with exactly two columns: `id` and `model` (predicted string label matching `configs/labels.json`).
- **Submission Hardware:** Standard Kaggle GPU acceleration (T4 vs P100 vs T4x2) `[verify]`. All inference pipelines must be optimized and verified for single-T4 (16 GB VRAM) execution or T4x2 device sharding if permitted.

## 4. Phase 0: EDA & Data Audit (`docs/eda_report.md`, `configs/labels.json`)

Phase 0 is a strictly non-modeling data audit executed via `/eda`. Findings are compiled into `docs/eda_report.md` to inform feature engineering and fold splitting.

### 4.1 Data Distribution & Schema Audit
- **Class Balance:** Measure exact sample counts per class across the 18 target models. Establish whether the training distribution is uniform or imbalanced.
- **Passage Lengths:** Calculate character, word, and subword token length distributions per class (min, 25%, median, 75%, max, IQR). Check whether lightweight models systematically produce shorter answers than frontier models.
- **Missing & Duplicate Texts:** Audit for exact text duplicates, near-duplicates across rows, and missing values.

### 4.2 Prompt Grouping & Leakage Audit
- Check whether `train.csv` and `test.csv` contain explicit `prompt_id`, `topic_id`, or metadata columns.
- Test whether multiple passages in `train.csv` or `test.csv` are completions to the identical underlying prompt (e.g., via pairwise Jaccard similarity, shared leading text, or semantic embeddings).
- **Cluster-Purity Check for Prompt Reconstruction:**
  If prompt groups are absent and must be reconstructed via sentence embeddings:
  1. Strip all markdown, bullet points, leading indentation, and formatting markers from passages.
  2. Embed sanitized passages with an embedding model (e.g., `bge-small-en-v1.5` or `all-MiniLM-L6-v2`).
  3. Cluster using a conservative distance threshold (hierarchical or DBSCAN).
  4. **Purity Test:** Assert that clusters exhibit high model diversity (i.e., multiple distinct LLM labels per cluster). Any cluster dominated by a single model or family indicates clustering on **stylistic footprint** rather than prompt topic, which would cause severe label leakage across folds.

### 4.3 Formatting Survival & Text Artifacts
Examine raw text across classes for the presence and preservation of layout markers:
- Newlines (`\n`, `\n\n`) and tab characters (`\t`).
- Markdown formatting: headers (`###`, `##`), bolding (`**`), italics (`*`), blockquotes (`>`), code blocks (```` ``` ````).
- List styling: bullet characters (`-`, `*`, `•`) vs. numbered lists (`1.`, `1)`).
- Typography: ASCII vs curly quotes (`"`, `”`, `'`, `’`), em-dashes (`—`), en-dashes (`–`), double spaces (`  `), and trailing whitespace at line ends.

### 4.4 Sklearn `char` Analyzer Collapse Verification
Run the mandatory 2-line test to verify that `TfidfVectorizer(analyzer='char')` collapses newline characters into whitespace:

```python
from sklearn.feature_extraction.text import TfidfVectorizer
vec = TfidfVectorizer(analyzer='char', ngram_range=(1, 2)).fit(["a\nb"])
print("Vocabulary:", vec.get_feature_names_out())
# Output demonstrates that '\n' is treated as a space separator, yielding ['a ', ' b'] instead of newline-preserving n-grams.
```
*Implication:* Confirms the necessity of pre-vectorization Unicode private-use mapping in `src/text_utils.py`.

### 4.5 Passage Truncation & Ending Audit
- Analyze passage termination patterns per class.
- Check whether passages terminate with standard punctuation (`.`, `!`, `?`, `"`) or if cutoffs occur mid-sentence or mid-word due to hard token truncations.
- Check whether specific models exhibit signature closing formulations or missing terminal punctuation.

## 5. Validation Design & Full OOF Contract

### 5.1 Folds Specification
- **Strategy:** `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)`.
  - `group`: Prompt identifier (explicit prompt ID or validated reconstructed prompt cluster).
  - `stratify`: Target LLM label (`model`).
- **Persistence:** Folds are computed exactly once via `/make-folds` and saved to `folds/folds.parquet` with the mandatory schema:
  - Columns: `id` (passage ID), `fold` (integer 0–4), `group` (group string/int), `model` (target label).
  - **Rule:** `folds/folds.parquet` is strictly frozen and never regenerated.

### 5.2 Shuffled-Label Leakage Check
To verify that the cross-validation harness has no subtle data or group leakage:
- Permute the target labels (`model`) randomly across the dataset.
- Train the Stage 1 baseline classifier inside the 5-fold harness on permuted labels.
- **Pass Criterion:** Out-of-fold balanced accuracy must be near chance level:

$$\text{Balanced Accuracy}_{\text{shuffled}} \approx \frac{1}{18} \approx 0.0556$$

Any statistically significant deviation above chance indicates structural feature leakage or fold overlap.

### 5.3 Full OOF Artifact Contract
Every experiment `<exp>` executed locally or on GCP must output a standardized artifact bundle under `artifacts/<exp>/` containing:
1. `oof.npy`: `np.ndarray` of type `float32`, shape $(N_{\text{train}}, 18)$, where each row sums to $1.0 \pm 1e-3$ (probabilities, never raw logits). Rows strictly aligned with `folds/folds.parquet`; columns ordered according to `configs/labels.json`.
2. `test.npy`: `np.ndarray` of type `float32`, shape $(N_{\text{test}}, 18)$, representing the unweighted arithmetic mean of probabilities predicted by the 5 fold models on `test.csv`.
3. `metrics.json`: Summary JSON storing:
   - `balanced_accuracy_argmax`: Macro-recall using standard $\text{argmax}$.
   - `balanced_accuracy_prior_divided`: Macro-recall dividing probabilities by training prior $\pi_{\text{train}}(k)$.
   - `per_class_recall`: Mapping of class label to individual recall score.
4. `confusion_matrix.csv`: $18 \times 18$ confusion matrix formatted with true labels as rows and predicted labels as columns (under prior-divided decisions).
5. `config.yaml`: Frozen snapshot of all hyperparameters, seeds, and feature flags.
6. `env.txt`: Complete package environment dump (`pip freeze`).
7. `git_commit.txt`: Commit SHA matching the codebase state during training.

**Contract Verification:**
Every experiment must pass:
```bash
python .agent/skills/oof-contract/scripts/validate_oof.py artifacts/<exp>/oof.npy folds/folds.parquet configs/labels.json --save-dir artifacts/<exp>
```
Upon passing, one summary row is appended to `results.csv`, and artifacts are mirrored to `$BUCKET/oof/<exp>/` and `$BUCKET/test/<exp>/`.

### 5.4 Model Selection & Improvement Threshold
To prevent adopting branches that win purely due to fold-to-fold variance or multiple hypothesis testing, every prospective model or ablation is evaluated against the current best reference system using paired fold differences:

$$\Delta_f = \text{score}_f(\text{new}) - \text{score}_f(\text{reference}) \quad \text{for } f \in \{0, 1, 2, 3, 4\}$$

**Acceptance Gate:**
A new model or component is retained if and only if:

$$\text{mean}(\Delta) > \text{sd}(\Delta) \quad \text{AND} \quad \Delta_f > 0 \text{ in at least 4 of the 5 folds}$$

*Note:* Because training folds share 75% of their training instances across splits, fold scores are positively correlated and sample variance is slightly underestimated. This criterion serves as an empirical operational guardrail against noise rather than a formal hypothesis test.

## 6. Modeling Stages (Gated by Grouped-CV Ablations)

### 6.1 Stage 1: Sparse Linear Baseline (`/baseline`)
A pure linear stylometric baseline executed inside each fold using `sklearn.pipeline.Pipeline`. All feature extractors and transformers are fit strictly on training-fold rows.

#### Feature Extraction Architecture:
1. **Unicode Private-Use Layout Mapping (`src/text_utils.py`):**
   Before character n-gram extraction, map multi-character structural tokens to single Private-Use Area (PUA) Unicode characters using longest-match-first replacement:
   - `###` $\to$ `\uE002`
   - `##` $\to$ `\uE003`
   - `**` $\to$ `\uE004`
   - Line-anchored bullet regex: `(?m)^[ \t]*[-*•][ \t]+` $\to$ `\uE005` (never use `\s` which consumes newlines).
   - Line-anchored numbered list regex: `(?m)^[ \t]*\d+[.)][ \t]+` $\to$ `\uE006`.
   - Structural newlines (applied **after** list handling): `\n\n` $\to$ `\uE000`, single `\n` $\to$ `\uE001`.
   - Single em-dash `—` is omitted from replacement (standard character n-grams capture it natively).
   - *Interaction with `char_wb`:* Character n-grams with word boundaries (`char_wb`) split tokens on whitespace. Because PUA tokens replace newlines and bullets with non-whitespace characters, verify whether boundary padding attaches to adjacent words or generates standalone boundary n-grams.
2. **N-Gram TF-IDF Feature Union:**
   - `char` n-grams: range $(2, 6)$, `lowercase=False`, `sublinear_tf=True`, `dtype=np.float32`.
   - `char_wb` n-grams: range $(3, 5)$, `lowercase=False`, `sublinear_tf=True`, `dtype=np.float32`.
   - `word` n-grams: range $(1, 3)$, `lowercase=False`, `sublinear_tf=True`, `dtype=np.float32`.
   - RAM & Dimension Tuning: Pilot memory consumption on Fold 0 to set `min_df` and `max_features` constraints `[verify values]` to ensure peak pipeline RAM remains within host limits.
3. **Dense Layout Scalar Counts:**
   - Custom transformer extracting: double space count (`  `), trailing line whitespace count (`(?m)[ \t]+$`), and indentation depths.
   - Scaled using `MaxAbsScaler` (preserves sparsity and bounds dense features).
4. **Classifier & Probability Calibration:**
   - Primary: `LogisticRegression(C=1.0, max_iter=1000)`. Run a 1-fold solver pilot comparing `lbfgs`, `saga`, and `SGDClassifier(loss='log_loss')` to establish throughput and convergence.
   - Linear Support Vector Alternative: `LinearSVC(C=1.0)` with default `dual` (`dual=True` or `'auto'`; never `dual=False` since $N_{\text{features}} \gg N_{\text{samples}}$). Because `LinearSVC` does not output probabilities, it must be wrapped in `CalibratedClassifierCV(estimator=LinearSVC(), method='sigmoid', cv='prefit')` trained on an internal sub-split (adds $\approx 5\times$ computational overhead).

### 6.2 Stage 1b: Prefix & Suffix TF-IDF Ablation (`no workflow yet`)
- **Hypothesis:** LLMs frequently exhibit distinctive opening greetings/acknowledgments ("Certainly!", "Here is a breakdown:") or trailing disclaimers/sign-offs.
- **Method:** Extract separate TF-IDF feature sets on the first 25 words and the last 25 words of each passage.
- **Constraints & Risks:** Passages in this competition range down to 40 words. On short passages, prefix (25 words) and suffix (25 words) exhibit an overlap of at least 10 words. Furthermore, if Phase 0 reveals that passages are synthetically truncated mid-sentence, suffix signals will be compromised.
- **Gate:** Retain only if isolated ablation meets Section 5.4 improvement criteria.

### 6.3 Stage 2: Stylometric Features + Tabular Stacker (`no workflow yet`)
Combines explicit stylometric feature engineering with Stage 1 out-of-fold probability distributions in a gradient boosted decision tree (LightGBM).

#### Extracted Stylometric Features:
- **Punctuation & Syntax Densities:** Semicolons, colons, Oxford commas, em-dashes, exclamation marks, parentheses, ellipsis counts per 100 tokens.
- **Structural Densities:** Ratio of markdown bolding to plain text, list item frequency, average items per list, heading depth distribution.
- **Length Statistics:** Mean and standard deviation of sentence lengths, paragraph lengths, and type-token ratios (TTR / lexical richness).
- **Whitespace Signatures:** Exact frequencies of double spaces between sentences and trailing spaces.
- *(Note on POS N-Grams):* Part-of-Speech n-grams (via spaCy/NLTK) are deferred due to inference latency overhead unless an ablation demonstrates clear orthogonal signal.

#### Tabular Stacking & Distribution Shift Warning:
- Input to LightGBM stacker includes the 18 Stage 1 OOF probability columns plus engineered stylometric features.
- **Distribution Shift Hazard:** Fold-averaged test predictions ($\frac{1}{5} \sum_{f} \hat{P}_f(y \mid x_{\text{test}})$) are mathematically smoother and have lower variance than individual out-of-fold predictions ($P_{\text{OOF}}$). A stacker trained on raw OOF probabilities will observe a distribution shift at test time.
- **Diagnostic Requirement:** Plot and compare the maximum probability histograms ($\max_k P_k$) between OOF and test sets. Apply temperature scaling to OOF probabilities prior to training the stacker if sharp overconfidence is observed.

### 6.4 Stage 3: Fine-Tuned Neural Classifiers (`/gcp-train`)
Fine-tune transformer architectures on the attribution task.

#### 1-Fold Candidate Selection Pilot:
Before launching expensive 5-fold training runs, conduct a 1-fold pilot (Fold 0) on GCP L4 to benchmark candidate architectures:
1. **Decoder LLM (0.5B to 3B parameters):** E.g., `Qwen/Qwen2.5-0.5B`, `Qwen/Qwen2.5-1.5B`, or `Qwen/Qwen2.5-3B` with LoRA (rank 16, alpha 32 on attention and MLP projections).
   - Compare **mean pooling** across sequence tokens vs. **last-token pooling**.
   - Architecture: Single 18-way classification head. (A hierarchical 6-way lab auxiliary loss head is tested only as a secondary ablation).
2. **Encoder-Based Transformer:** `roberta-large` (and `deberta-v3-large`).
   - If DeBERTa is used, explicit newline replacement tokens must be injected during tokenization to prevent DeBERTa's tokenizer from discarding whitespace structure.

#### Full 5-Fold Training:
The winning candidate from the 1-fold pilot is trained across all 5 folds on GCP L4 Spot instances, subject to Section 5.4 improvement threshold.

#### 7–8B QLoRA Gate:
Scaling to a 7B–8B model (e.g., `Qwen2.5-7B` or `Llama-3.1-8B`) is strictly gated:
- Pursue **only if** 1B–3B decoders show a substantial positive slope over RoBERTa.
- **Inference Hardware Constraint:** An 8B model in `fp16` requires $\approx 16$ GB VRAM solely for weights, exceeding the memory of a single Kaggle T4 GPU during inference. If pursued, the team must decide prior to training whether offline inference will rely on an offline `bitsandbytes` 4-bit wheel or tensor sharding across 2x T4 GPUs `[verify]`.

### 6.5 Stage 4: Conditional Perplexity Probes (`no workflow yet`)
- **Concept:** Query open-weight foundation models corresponding to the target model families (e.g., Qwen, Llama, Gemma) to compute sequence log-probabilities, cross-model log-prob differences, and token rank distribution buckets (`top-1`, `top-10`, `top-100`, `>1000`).
- **Condition:** Feature extraction is computationally heavy and must fit within Kaggle's 9-hour offline runtime. Pursue only if an isolated ablation produces a decisive boost in grouped CV.

### 6.6 Stage 5: Conditional Sibling Specialists (`no workflow yet`)
- **Trigger:** Evaluate the $18 \times 18$ OOF confusion matrix from Stage 1–3 models. If misclassifications are overwhelmingly concentrated within specific sibling sub-trees:
  - OpenAI siblings: `gpt-5.5` vs `gpt-5.6-luna` vs `gpt-5.6-sol` vs `gpt-5.6-terra`
  - Anthropic siblings: `claude-opus-4-6` vs `claude-opus-4-8` vs `claude-opus-5`
  - Google siblings: `gemini-3.6-flash` vs `gemini-3.7-flash` vs `gemini-3.8-flash`
- **Method:** Train specialized pairwise or cluster classifiers focused exclusively on sibling discrimination. Evaluate strictly via nested cross-validation to prevent optimistic evaluation bias.

## 7. Ensembling, Calibration & Post-Processing

### 7.1 Calibration & Probabilistic Blending
1. **Probability Calibration:**
   Before blending, calibrate raw probabilities from each distinct model family (TF-IDF LR, LightGBM, Neural Classifiers) using **regularized vector scaling** or **temperature scaling** fitted strictly inside nested CV folds.
2. **Ensemble Aggregation:**
   - Optimize blend weights via regularized multinomial logistic regression or Nelder-Mead optimization on log-loss over calibrated OOF probabilities.
   - Combine predictions via weighted log-probability averaging:

$$\log P_{\text{ensemble}}(y=k \mid x) = \sum_{m=1}^{M} w_m \log P_m(y=k \mid x) - \log Z$$

### 7.2 Base Decision Rule
Under the balanced accuracy metric, the definitive baseline classification rule normalizes posterior probabilities by the observed training prior:

$$\hat{y} = \arg\max_{k \in \{1,\dots,18\}} \frac{P_{\text{blend}}(y=k \mid x)}{\pi_{\text{train}}(k)}$$

*Invariant:* Never fit unregularized 18-class multiplier weights directly on raw OOF predictions to prevent catastrophic overfitting to small sample variations.

### 7.3 Transductive Test Post-Processing (Strictly Conditional)
Transductive post-processing leverages the full test set distribution and is **strictly conditional** on Phase 0 confirming that `test.csv` contains prompt-grouped structures:

1. **Sinkhorn-Knopp Optimal Transport:**
   - *Within-Prompt Constraint:* If Phase 0 proves each prompt in the test set receives completions from distinct models (at most one instance per model per prompt), the test assignment matrix within a prompt block forms a matching problem.
   - Standard Sinkhorn-Knopp enforces exact row and column marginal equality. If not all 18 models are present for every prompt, an **unbalanced Sinkhorn** or a formulation with a dummy "unassigned" slack column must be employed.
   - *Global Marginal Estimation:* Global test class marginals can be estimated transductively via Expectation-Maximization (EM) or Black Box Shift Estimation (BBSE).
   - *Tension & Risk:* Acknowledged conflict with Rule `00-project-context.md` ("Never estimate or use test priors"). Transductive marginal adaptation must be validated on CV under simulated prior shift before adoption.
2. **Pseudo-Labeling:**
   - Semi-supervised pseudo-labeling on test passages must be validated by holding out an entire training fold as a simulated unlabelled test set. Adopt only if it demonstrates consistent balanced accuracy gains without exacerbating sibling confusion.

## 9. Kaggle Offline Packaging & Submission Policy

### 9.1 Offline Artifact Packaging
All dependencies and model artifacts must be pre-packaged and uploaded as Kaggle Private Datasets:

### 9.2 Offline Verification Gates
Execute the following verification gates inside a Kaggle notebook with **internet toggled OFF** on the competition submission GPU:
1. **Precision & T4 Stability Check:**
   Kaggle T4 GPUs lack native hardware support for `bfloat16`. All neural inference pipelines must execute under `float16`. Validate that `fp16` inference does not suffer from underflow/overflow (producing NaN logits) in attention layers.
2. **Fold 0 Reproduction Test:**
   Load offline artifacts using `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` from `/kaggle/input/...`:
   - Assert: $|\text{Balanced Accuracy}_{\text{offline}} - \text{Balanced Accuracy}_{\text{CV}}| \le 0.002$.
   - Assert: Prediction agreement between offline inference and recorded OOF predictions $\ge 99.5\%$.
   - Assert: Mean absolute probability difference $< 1e-2$ under `fp16`.
   - Verify that `train.csv` is accessible in the submission session for verification tests `[verify]`.
3. **5-Fold Smoke Test:**
   Iterate through all 5 fold models/adapters with a dummy synthetic batch to ensure every weight file, tokenizer configuration, and checkpoint key resolves without error.

### 9.3 Submission Policy
- **No Public Leaderboard Tuning:** Never modify thresholds or select features based on public leaderboard feedback. Grouped cross-validation is the sole objective decision criterion.
- **Final Selection Policy:** Select exactly two final submissions:
  1. *Submission 1 (Performance):* The highest-scoring ensemble blend under 5-fold grouped CV.
  2. *Submission 2 (Robustness):* A simpler, highly regularized architecture (e.g., Stage 1 TF-IDF + calibrated RoBERTa) with minimal post-processing to hedge against extreme prior or stylistic shift.
- **Execution Budget:** Complete a full timed dry-run on Kaggle offline infrastructure. Ensure total runtime is $\le 4.5$ hours (well under the 9.0-hour disqualification threshold).

## 10. Key Risks & Mitigation Strategies

| Risk | Description | Impact | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| **CV Leakage from Grouping** | Reconstructed prompt clusters inadvertently group by stylistic footprint rather than prompt topic. | Severe CV optimism; catastrophic LB drop. | Run Phase 0 cluster-purity check; assert high model diversity within clusters; run shuffled-label leakage check. |
| **Prior Shift** | Public and private test sets exhibit class prior distributions radically different from training data. | Severe metric penalty under balanced accuracy. | Divide raw probabilities by training class priors $\pi_{\text{train}}(k)$; evaluate transductive Sinkhorn only under simulated shift. |
| **Sibling Confusion Ceiling** | Model families (e.g., `gpt-5.6-*` or `claude-opus-*`) share identical stylometry and cannot be separated. | Accuracy plateau across all models. | Develop Stage 5 sibling specialist models; isolate differential features (rare tokens, fine-grained length distributions). |
| **Formatting Stripping** | Kaggle test set text has stripped newlines or normalized whitespace compared to train. | Feature invalidation for Stage 1 & 2. | Perform Phase 0 formatting audit on `test.csv`; build baseline models resilient to stripped whitespace. |
| **Spot Preemption & Cost** | Spot GPU instances interrupted during multi-hour neural training. | Lost progress; cost overruns. | Sync checkpoints to GCS every $N$ steps; enforce automated `scripts/run_job.sh` resume logic; adhere to 100-step cost pilots. |
| **T4 Precision Mismatch** | Models trained in `bf16` on GCP L4 produce NaNs or numerical drift when run in `fp16` on Kaggle T4. | Notebook failure or degraded predictions. | Mandate Kaggle offline reproduction gate; test `fp16` numerical stability before packaging. |
| **Public LB Overfitting** | Making modeling choices based on noisy public LB feedback. | Regression on private test set. | Enforce strict grouped-CV decision gate (Section 5.4); ignore public LB shifts within noise bounds. |

## 11. Conflicts & Kit Discrepancies

The following table documents all discrepancies and conflicts between the user specification, project rules, and existing `.agent/` kit files. In accordance with project instructions, these conflicts are cataloged explicitly without silent resolution:

### 11.1 `LinearSVC` Dual Formulation
- **Specification:** `LinearSVC` must use default `dual` (`dual=True` or `'auto'`), explicitly noting: "not `dual=False`, since features far exceed samples".
- **Kit Workflow (`.agent/workflows/baseline.md`, line 11):** Explicitly specifies `CalibratedClassifierCV(LinearSVC(C=1.0, dual=False))`.
- **Conflict Analysis:** In sparse high-dimensional text classification where $N_{\text{features}} \gg N_{\text{samples}}$ (e.g., hundreds of thousands of n-grams vs. $\approx 4,000$ passages), solving the dual problem is significantly faster and standard in scikit-learn. The kit workflow forces `dual=False` (primal), which is computationally inefficient for this regime.

### 11.2 Bullet and Numbered List Regular Expressions
- **Specification:** Requires line-anchored regex `(?m)^[ \t]*[-*•][ \t]+` for bullets and `(?m)^[ \t]*\d+[.)][ \t]+` for numbered lists. Explicitly mandates: "never `\s`, which matches newlines".
- **Kit Rules & Workflow (`.agent/rules/00-project-context.md`, lines 24–25; `.agent/workflows/baseline.md`, line 5):** Specifies `(?m)^[-*]\s+` for bullets and `(?m)^\d+\.\s+` for numbered lists.
- **Conflict Analysis:** The kit's regex uses `\s+`, which matches newline characters, potentially causing the regex to span across line boundaries. Additionally, the kit's pattern omits indentation (`[ \t]*`), bullet character `•`, and closing parenthesis numbered list delimiters (`1)`).

### 11.3 Missing Baseline Workflow Details
- **Specification:** Specifies:
  1. Pilot solver selection (`lbfgs`, `saga`, `SGDClassifier(loss='log_loss')`).
  2. Set `min_df` and `max_features` based on Fold 0 RAM measurements `[verify values]`.
  3. Scale layout counts with `MaxAbsScaler`.
  4. Ensure vectorizer `dtype=float32`.
- **Kit Workflow (`.agent/workflows/baseline.md`):** Omits solver piloting, does not mention `min_df` / `max_features` RAM tuning, omits `MaxAbsScaler` for dense counts, and omits explicit `dtype=float32` vectorizer specifications.

### 11.4 Decision Rule vs. Transductive Test Prior Estimation
- **Kit Non-Negotiable Rule (`.agent/rules/00-project-context.md`, line 6):** "Final decision rule: argmax_k P_train(y=k|x) / pi_train(k). Never estimate or use test priors for the decision."
- **Specification (Section 7):** Proposes transductive post-processing including Sinkhorn-Knopp marginal matching and global test class marginal estimation via EM or BBSE.
- **Conflict Analysis:** Estimating test priors via EM/BBSE or adjusting marginals directly violates the non-negotiable rule in `00-project-context.md`. The plan reconciles this by classifying transductive methods as strictly conditional research options requiring simulated prior shift validation prior to adoption.

### 11.5 Cloud Run Jobs Fallback Implementation Status
- **Specification (Section 8):** Characterizes Cloud Run Jobs GPU fallback as "(contingency, not implemented in `.agent/`)".
- **Kit Files (`.agent/rules/00-project-context.md`, `.agent/rules/10-compute-and-cost.md`, `.agent/skills/gcp-gpu-job/SKILL.md`):** Provide concrete implementation commands and architectural rules for Cloud Run Jobs (`--gpu=1 --no-gpu-zonal-redundancy`).
- **Conflict Analysis:** While code snippets exist in rules and skills, there is no corresponding workflow file (e.g., `.agent/workflows/cloud-run-train.md`). Thus it remains a manual contingency.
